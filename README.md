# 課堂互動工具 V2.32.0 — 第四波活動模組整合

以 V2.31.0 為基礎，將「開放文字／文字牆」與「匿名提問牆＋認同＋回應」整合為**「文字交流與提問」**。活動入口從 9 種精簡至 **8 種**。

## 第四波變更

- 統一教師端入口：「文字交流與提問」，內含**短答蒐集**、**匿名提問**兩種流程。
- **短答蒐集**：保留教師端文字牆、詞雲、匿名或顯示學生、字數及輸入提示設定；可放入完整 Course。
- **匿名提問**：保留學生多則匿名發問、＋1 認同、匿名同儕回應及教師刪除功能；僅限獨立 Activity Session，不允許加入完整 Course，防止互動資訊隔離失效。
- 兩種流程的設定各自保留，切換流程不覆蓋另一方；僅針對當前流程驗證與發布。
- 自動轉換舊活動 `open-text` → `text-exchange + responses`，`question-wall` → `text-exchange + questions`；保留原始題目與設定。
- **執行層維持舊模式**：新活動分享、Session 及 Course Snapshot 仍輸出 `open-text` 或 `question-wall`，因此沿用既有學生端、教師統計、資料庫 RPC、歷程鍵與舊分享連結。
- 更新活動清單及 Course 選擇器的流程標示；避免誤把匿名提問的信心程度欄位加入編碼。
- 修正「沒有 allowReplies 欄位的舊設定」預設值與編輯器預設勾選不一致。
- **無新增 Supabase 資料表、欄位或 RPC，已部署 V2.31.0 者不用重新執行 SQL。**

## 部署提醒

1. 解壓縮並將全部檔案更新至 GitHub Pages 專案。
2. 建議部署前匯出教材備份；首次打開新版教師端會將瀏覽器原有的舊模組編輯活動升級為統一格式（原始兩種設定保留），Session 與分享 QR 不受影響。
3. 測試「短答蒐集」可用 Course；「匿名提問」需用獨立活動 Session。
4. 程式靜態檢查不等於已通過 Supabase 實機跨裝置測試。

# 課堂互動工具 V2.31.0 — 第三波活動模組整合

本版以 V2.30.0 原始檔為基礎，將「預測 → 揭曉 → 再判斷」與「逐步揭露」整合成 **「資訊揭露與修正」**，模組數量從 **10 種精簡為 9 種**。

## V2.31.0 變更內容

- 教師端模組選擇器新增統一入口「資訊揭露與修正」，內含 **預測揭曉**與**逐步揭露**兩種活動流程。

- 逐步揭露：教師一項一項揭露材料資訊，學生在每一階段重新作答；沿用 `progressive-reveal` 執行模式與 `clue-N` 作答鍵。

- **既有舊分享連結、Session、作答紀錄與 Course Snapshot 不需轉換**；建立新 Session 時仍使用原有執行模式，避免中斷教師控制台與學生端功能。
- 課程活動選擇器、Session 選擇器與活動清單標示目前選定的流程。
- **未修改 Supabase SQL / RPC / 資料表**。既有資料庫已完成 V2.30.0 設定者不必因這次整合重新執行 SQL。

## V2.26.0 — 第三波：小組共識

V2.26.0 延續 V2.24～V2.25 的學生彼此互動，新增第三波第三項能力：**小組共識**。這次不只加入一個活動畫面，也建立可重用的 Session 分組底層，讓後續的排序、分類或其他活動可以沿用同一套「小組／組員／共同提交」資料結構。

> **重要：V2.26.0 有 Supabase schema / RPC 更新。** 若使用跨裝置雲端 Session，升級後請到 Supabase SQL Editor **重新執行整份 `supabase-setup.sql`**。本機模式不需要資料庫更新。

## V2.26.0 新增功能

### 👥 第 14 種活動模組：小組共識

基本流程：

1. 學生先完成 **個人判斷**。
2. 教師依目前加入人數，以每組約 2～6 人自動分組。
3. 教師開放 **小組討論** 階段。
4. 學生看到自己的組別與組員，討論後共同提交 1 份答案與理由。
5. 同組任何成員都能更新同一份共識，不會產生多份互相衝突的組答案。
6. 教師端同時比較「個人判斷分布」與「小組共識分布」。
7. 教師可以查看每組成員、共識答案、理由，以及最後更新者。
8. 課後摘要會列出個人完成率、已形成共識組數與各組結果。

### 活動編輯器

可以設定：

- 核心提問。
- 2～8 個共識選項。
- 建議每組人數（2～6 人）。
- 共識理由提示。
- 理由字數上限（30～500 字）。
- 是否要求小組必填理由。

V2.26.0 第一版先以「單選共識題」完成完整教學流程；分組底層本身不綁單一題型。

### 教師控制台

新增：

- 個人作答／小組討論兩階段切換。
- 自動分組與重新分組。
- 依目前參與人數平均分配，盡量避免出現單獨 1 人的小組。
- 個人判斷即時分布。
- 小組共識即時分布。
- 每組組員與共同答案檢視。
- 重新分組時明確提醒既有小組共識將清除。

### 學生端

個人階段：

- 學生只先做自己的判斷。
- 教師尚未開放小組階段時，可以保留／更新個人答案。

小組階段：

- 顯示「第 N 組」與組員名單。
- 保留自己的個人判斷作為討論參照。
- 同組共用一份小組答案與理由。
- 任一組員提交／更新後，同組其他裝置透過 Realtime 或輪詢取得最新結果。

## 可重用的小組資料層

Supabase 新增：

- `session_groups`：每個 Session 的小組。
- `session_group_members`：學生與小組關係。
- `group_consensus_submissions`：每組共同提交結果。

新增 RPC：

- `assign_session_groups()`：教師自動分組／重新分組。
- `submit_group_consensus()`：組員提交或更新本組共同答案。

這套分組資料並不只服務 `group-consensus`，後續可以直接讓排序、分類或其他活動接上。

## 升級方式

1. 備份目前教材資料。
2. 將網站檔案更新成 V2.26.0。
3. 如果使用 Supabase，打開 SQL Editor。
4. 貼上並執行 V2.26.0 的完整 `supabase-setup.sql`。
5. 不需要先刪除既有教材、Session 或學生作答資料。

## V2.26.0 限制

- 小組共識目前先作為「單一活動 Session」使用，尚未放進完整 Course Session。
- 第一版小組答案為單選題；分組底層已可供未來其他模組沿用。
- 真正跨裝置的同步仍需設定 Supabase；未設定時可在同一瀏覽器用本機 Session 測試。
