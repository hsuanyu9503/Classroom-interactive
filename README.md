## 重要：部署順序

**這版有 Supabase SQL 升級，僅更新 GitHub Pages 不足以啟用新版雲端 Course Session。**

1. **備份現有 Supabase 資料庫及網站／教材資料**。
2. 已部署舊版資料庫：在 Supabase SQL Editor 執行 `upgrade-v2.35.0-course-all-modules.sql`。首次部署完整資料庫可使用壓縮檔內已整合升級的 `supabase-setup.sql`；不必兩份都執行。
3. 更新 GitHub Pages 上的**全部網站檔案**，不只替換 `index.html`。刷新瀏覽器快取。
4. 在教師端建立**新的** Course Session（請勿用之前仍在進行的舊 Course Session 驗收）。
5. 用教師一台裝置＋至少兩名學生裝置實際測試：節點切換、再次判斷、逐層公開、匿名提問、小組共識、即時立場、Session 結束。

## Course、Course Session 的差別

- **Course Session（建議正式課堂使用）**：老師控制目前節點和公開階段，學生同步進入對應活動；私有分階段內容保存在 Supabase 受限資料表 `course_private_nodes`，只在目前公開階段回傳學生。包含逐層思辨、預測揭曉、逐步揭露的 Course Session **必須設定 Supabase**，以防完整快照直接包含未公開內容。
- **直接分享 Course 連結（自主瀏覽）**：沒有老師同步控制及多人互動 Session 權限。此分享是教師主動提供的自主學習快照；不適合作為保密或即時控制的教學工具。若活動必須由老師依階段公開，請改用雲端 Course Session。

## 主要修改

- 每一個 Course Node 獨立標記 `node_ref`，同一活動重複引用也不混用作答與討論資料。
- 匿名提問、認同與回覆、分組、共識提交、立場事件與歷程皆依節點隔離。
- 教師切換節點時重設目前活動階段；防止舊節點學生請求寫入新節點。
- Course 學生完成回報以 iframe 的節點與活動 ID 驗證，連續互動型活動可手動回報完成。
- 同一節點的同步更新**不重建 iframe**，避免教師揭露資訊時重置未送出文字。
- 學生端公開 Course 快照移除逐層思辨未公開層、預測揭曉答案、逐步揭露的後續線索；伺服器依公開階段回傳必要內容。
- 沿用原版 CSS 與 V2.34.9 手機版內距修正，不變更原有教材 JSON 資料格式。
